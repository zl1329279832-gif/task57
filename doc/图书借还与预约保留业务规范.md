# 图书借还与预约保留业务规范

> 面向集成方与馆员操作手册。本文档是借还 + 预约保留行为的**唯一权威说明**，代码实现以 `BorrowController` 和 `ReservationController` 为准。

---

## 1 概述

系统存在**两条并行的借还路径**：

| 路径 | Controller | URL 前缀 | 特征 |
|------|-----------|----------|------|
| 基础借还 | `BorrowController` | `/borrow` | 只做借/还/续借，**不感知预约队列** |
| 增强借还 | `ReservationController` | `/reservation` | 借/还均与预约保留联动 |

> **核心问题**：合作方目前调用的是 `/borrow/borrowBook` 和 `/borrow/returnBook`。
> 该路径还书时**永远将图书置为可借（isBorrowed=0）**，完全跳过预约保留窗口。
> 一旦馆员手工通过此路径还书，排队中的预约人不会被通知、保留窗口不会启动，
> 图书直接被释放为公开可借状态——这就是"保留窗口乱套"的根因。
>
> **集成方应统一使用 `/reservation/*` 路径**（详见 §5 Canonical API）。

## 2 状态机定义

### 2.1 预约五态（`reservation.status`）

`Reservation` 模型中定义了 5 个 `static final byte` 常量：

| 常量名 | 值 | 中文名 | 含义 |
|--------|---:|--------|------|
| `STATUS_WAITING` | 0 | 排队中 | 读者已预约，等待前面的人取书或过期 |
| `STATUS_RESERVED` | 1 | 已保留 | 轮到该读者，72 小时保留窗口正在倒计时 |
| `STATUS_FULFILLED` | 2 | 已完成 | 读者成功借走了保留的图书 |
| `STATUS_CANCELLED` | 3 | 已取消 | 读者或管理员主动取消 |
| `STATUS_EXPIRED` | 4 | 已过期 | 72 小时窗口到期未取，系统自动标记 |

**状态转换图**：

```
                        createReservation()
                              │
                              ▼
                    ┌───────────────────┐
                    │   WAITING (0)     │◄─────────────────────────┐
                    └────────┬──────────┘                          │
                             │                                     │
              ┌──────────────┼──────────────┐                      │
              │              │              │                      │
              │    triggerReservation()     │                      │
              │    (还书/取消顺延触发)       │                      │
              │              │              │                      │
              │              ▼              │                      │
              │    ┌───────────────────┐    │                      │
              │    │  RESERVED (1)     │    │                      │
              │    └──┬─────┬─────┬───┘    │                      │
              │       │     │     │         │                      │
              │       │     │     │         │                      │
    cancelReservation()     │  expireAndAdvance()                 │
              │       │     │     │         │                      │
              │       │     │     ▼         │                      │
              │       │     │ ┌─────────────────┐                 │
              │       │     │ │  EXPIRED (4)    │                 │
              │       │     │ └────────┬────────┘                 │
              │       │     │          │                           │
              │       │     │   triggerReservation()               │
              │       │     │   (为队列中下一位)                    │
              │       │     │          │                           │
              │       │     │          └───────────────────────────┘
              │       │     │                     (新的 WAITING → RESERVED)
              │       │     │
              │       │  consumeReservation()
              │       │  (读者来取书)
              │       │     │
              │       │     ▼
              │       │ ┌─────────────────┐
              │       │ │ FULFILLED (2)   │  ← 终态
              │       │ └─────────────────┘
              │       │
              ▼       │
    ┌─────────────────┐│
    │ CANCELLED (3)   ││  ← 终态
    └─────────────────┘│
                       │
     (若取消时 status=RESERVED，触发 triggerReservation() 顺延给下一位)
```

**关键规则**：

- 只有 `WAITING(0)` 和 `RESERVED(1)` 可以被取消。
- `FULFILLED(2)`、`CANCELLED(3)`、`EXPIRED(4)` 均为**终态**，不可逆转。
- `RESERVED(1)` 状态的预约被取消后，系统立即调用 `triggerReservation()` 将队列中下一个 `WAITING` 记录提升为 `RESERVED`，开启新的 72 小时窗口。

### 2.2 图书库存三态（`book_info.isBorrowed`）

`BookInfo.isBorrowed` 是 `TINYINT` 列，取值 0/1/2：

| 值 | 中文名 | 含义 |
|---:|--------|------|
| 0 | 可借 | 图书在架，任何人可借 |
| 1 | 已借出 | 图书已被某读者借走 |
| 2 | 已保留 | 图书已归还但被保留给预约队列首位读者 |

**状态转换图**：

```
                          borrowBook (基础/增强, 无人排队)
                         ┌─────────────────────────────────┐
                         │                                 │
                         ▼                                 │
               ┌──────────────────┐                        │
               │  0 - 可借        │                        │
               └────────┬─────────┘                        │
                        │                                  │
           borrowBook   │                                  │
           (CAS: 0→1)   │                                  │
                        │                                  │
                        ▼                                  │
               ┌──────────────────┐                        │
               │  1 - 已借出      │                        │
               └──┬──────────┬───┘                        │
                  │          │                             │
     returnBook   │          │  returnBook                 │
     (无人排队)    │          │  (有人排队)                  │
     (CAS: 1→0)   │          │  (CAS: 1→2)                │
                  │          │                             │
                  │          ▼                             │
                  │ ┌──────────────────┐                   │
                  │ │  2 - 已保留      │                   │
                  │ └────────┬─────────┘                   │
                  │          │                             │
                  │          │  borrowBook (保留人来取)     │
                  │          │  (CAS: 2→1)                 │
                  │          │                             │
                  └──────────┴─────────────────────────────┘
                       最终都回到 0(可借) 或 1(已借出)
```

**关键规则**：

- 所有状态变更均通过 **CAS（Compare-And-Swap）** 原子操作完成（详见 §7）。
- `isBorrowed=2` 是"逻辑占用"：书物理在馆，但仅对特定预约人可借。
- 保留状态下非预约人尝试借阅会被拒绝：`"该书已被保留给其他读者，您暂不可借"`。

## 3 两条借还路径行为对比

### 3.1 借书

| 维度 | `/borrow/borrowBook` (基础) | `/reservation/borrowBook` (增强) |
|------|-----------------------------|----------------------------------|
| 检查 `isBorrowed` | 仅允许 `== 0`（可借） | 允许 `== 0`（可借）或 `== 2`（已保留且当前人是保留人） |
| 预约保留感知 | **无**。不查询 reservation 表 | **有**。检查 `getActiveReservation()`，验证过期、身份、消费保留 |
| 当 `isBorrowed=2` 时 | 直接拒绝：`"库存不足（已经被借走）"` | 校验当前 userid 是否为保留人：是则 `consumeReservation()` 后借出；否则拒绝 |
| 当 `isBorrowed=0` 但存在 RESERVED 保留 | **无视保留，直接借走**（BUG 场景） | 检查保留是否过期 → 未过期则仅保留人可借 → 过期则 `expireAndAdvance()` |
| CAS 更新 | `casUpdateIsBorrowed(bookid, 0, 1)` | `casUpdateIsBorrowed(bookid, originalStatus, 1)`，`originalStatus` 可为 0 或 2 |
| 借阅上限检查 | `activeCount >= 5` 拒绝 | `activeCount >= 5` 拒绝 |
| 幂等性 | 无（重复借同本书会产生多条记录） | 无（同左） |

**基础路径的 BUG 场景**：

```
1. 读者 A 预约了书 X（status=WAITING）
2. 书 X 当前被读者 B 借走（isBorrowed=1）
3. 读者 B 通过 /borrow/returnBook 还书
   → 基础路径将 isBorrowed 直接设为 0（可借），不调用 triggerReservation()
4. 读者 C（非预约人）通过 /borrow/borrowBook 借走书 X
   → 读者 A 的预约永远无法被满足
```

### 3.2 还书

| 维度 | `/borrow/returnBook` (基础) | `/reservation/returnBook` (增强) |
|------|-----------------------------|----------------------------------|
| 借阅记录 CAS 归还 | `returnBorrowCas(borrowid)` — 幂等 | 同左 |
| 预约队列检查 | **无**。永远 `isBorrowed: 1→0` | **有**。调用 `triggerReservation(bookid)` 检查队列 |
| 有人排队时 | 书直接变为可借（`isBorrowed=0`） | 书变为保留（`isBorrowed=2`），预约记录变为 RESERVED |
| 无人排队时 | `isBorrowed: 1→0` | `isBorrowed: 1→0`（行为一致） |
| 幂等性 | 多次调用安全（CAS `WHERE returnTime IS NULL`） | 同左 |

> **馆员手工还书注意事项**：如果馆员使用 `/borrow/returnBook`（基础路径）还书，
> 系统**不会**触发预约保留。即使有读者在排队，书也会被直接释放为公开可借。
> 这是当前合作方遇到问题的直接原因。

### 3.3 其他端点差异

| 端点 | `/borrow/*` 基础 | `/reservation/*` 增强 |
|------|------------------|----------------------|
| 续借 `/renewBook` | 有 | **无**（需通过基础路径续借） |
| 预约创建 `/create` | 无 | 有 |
| 预约取消 `/cancel` | 无 | 有（读者 + 管理员） |
| 排队查看 `/queue` | 无 | 有（管理员） |
| 排队调整 `/admin/adjustPosition` | 无 | 有（管理员） |
| 管理 CRUD（addBorrow/deleteBorrow 等） | 有 | 无 |

## 4 核心流程时序

### 4.1 完整生命周期：还书 → 保留 → 取书 / 过期顺延

```
读者 B (当前借书人)          系统                    读者 A (预约队列首位)    读者 D (队列第二位)
       │                      │                              │                      │
       │ returnBook           │                              │                      │
       │ (borrowid, bookid)   │                              │                      │
       │─────────────────────►│                              │                      │
       │                      │                              │                      │
       │              ①CAS: borrow.returnTime=now            │                      │
       │              (WHERE returnTime IS NULL)             │                      │
       │                      │                              │                      │
       │              ②triggerReservation(bookid)            │                      │
       │              SELECT * FROM reservation              │                      │
       │              WHERE bookId=? AND status=0            │                      │
       │              ORDER BY queuePosition ASC             │                      │
       │              LIMIT 1                               │                      │
       │                      │                              │                      │
       │              ③找到读者 A (WAITING, queuePos=1)      │                      │
       │              UPDATE reservation                     │                      │

       │                  reserveTime=now,                   │                      │

       │                      │                              │                      │

       │                      │                              │                      │
       │◄─────────── 返回 1 (成功) ──┐                       │                      │
       │                      │      │                       │                      │
       │            ┌─────────┴─── 72 小时保留窗口 ───┐      │                      │
       │            │                                 │      │                      │
       │            │  读者 A 可随时来取书              │      │                      │
       │            │  (reservation/borrowBook)        │      │                      │
       │            │                                 │      │                      │
       │            │       读者 A                     │      │                      │

       │            │         │                        │      │                      │
       │            │         │              ⑤检查 expiryTime │                      │

       │            │         │                        │      │                      │
       │            │         │              ⑥consumeReservation()                   │
       │            │         │              SET status=2(FULFILLED)                 │
       │            │         │                        │      │                      │
       │            │         │              ⑦CAS: book_info.isBorrowed              │

       │            │         │                        │      │                      │
       │            │         │              ⑧INSERT borrow 记录                     │
       │            │         │                        │      │                      │
       │            │         │◄──── 返回 1 (成功) ────┘      │                      │
       │            │         │                              │                      │

       │                      │                                                      │
       │                      │                                                      │
       │              ======== 如果 72 小时内读者 A 未来取书 ========                 │
       │                      │                                                      │
       │              ⑨某次 borrowBook 请求发现 expiryTime < now                      │
       │                      │                                                      │
       │              expireAndAdvance(reservationId_A):                             │
       │              UPDATE reservation SET status=4(EXPIRED)                       │
       │                      │                                                      │
       │              triggerReservation(bookid):                                    │
       │              SELECT ... WHERE status=0                                      │
       │              ORDER BY queuePosition LIMIT 1                                 │
       │                      │                                                      │
       │              ⑩找到读者 D (WAITING, queuePos=2)                              │
       │              UPDATE reservation                                             │
       │              SET status=1(RESERVED),                                        │
       │                  reserveTime=now,                                           │
       │                  expiryTime=now+72h                                         │

       │              读者 D 获得新的 72 小时保留窗口                                  │
       │                      │                                                      │
```

### 4.2 过期检测是惰性的（Lazy Expiration）

系统**没有**后台定时任务来扫描过期保留。过期检测仅在以下时机触发：

1. 有人调用 `/reservation/borrowBook` 时发现该书存在 `RESERVED` 保留 → 检查 `expiryTime`。
2. 如果已过期 → 调用 `expireAndAdvance()` → 标记 `EXPIRED(4)` → 为队列中下一位开启新窗口。

这意味着：

- 一本书可能在 `isBorrowed=2` 状态停留超过 72 小时，直到有人尝试借它。
- 过期不会自动将图书释放为 `isBorrowed=0`；只有当所有排队者都过期或队列为空时，书才会变为可借。

### 4.3 取消 RESERVED 预约的顺延

```
读者 A (当前保留人)          系统                     读者 D (队列下一位)
       │                      │                              │
       │ cancelReservation    │                              │
       │ (reservationId)      │                              │
       │─────────────────────►│                              │
       │                      │                              │
       │              ①查 status：RESERVED(1)                │
       │              wasReserved = true                     │
       │                      │                              │
       │              ②UPDATE reservation                    │
       │              SET status=3(CANCELLED)                │
       │                      │                              │
       │              ③triggerReservation(bookid)            │
       │              (因为 wasReserved=true)                │
       │                      │                              │
       │              ④读者 D: WAITING → RESERVED            │
       │              新的 72 小时窗口开始                    │
       │                      │                              │
       │◄─────────── 返回成功 ─                              │
```

## 5 Canonical API（集成方应使用的接口）

### 5.1 借还核心路径

| 操作 | **应使用** | 禁止使用 |
|------|-----------|---------|
| 借书 | `GET /reservation/borrowBook?userid=&bookid=` | ~~`GET /borrow/borrowBook`~~ |
| 还书 | `GET /reservation/returnBook?borrowid=&bookid=` | ~~`GET /borrow/returnBook`~~ |
| 续借 | `GET /borrow/renewBook?borrowid=` | 增强路径无续借端点 |

> **迁移指引**：只需将 URL 前缀从 `/borrow` 替换为 `/reservation`，参数不变。
> `/reservation/borrowBook` 和 `/reservation/returnBook` 是基础路径的**超集**，
> 在无预约的情况下行为完全一致。

### 5.2 预约管理路径

| 操作 | URL | 参数 |
|------|-----|------|
| 创建预约 | `GET /reservation/create` | `userid`, `bookid` |
| 取消预约 | `GET /reservation/cancel` | `reservationid` |
| 查看我的预约 | `GET /reservation/myList` | `userid` |
| 查看预约队列（管理员） | `GET /reservation/queue` | `bookid` |
| 管理员取消预约 | `GET /reservation/admin/cancel` | `reservationid` |
| 调整排队位置（管理员） | `GET /reservation/admin/adjustPosition` | `reservationid`, `newPosition` |

### 5.3 通用返回约定

| 返回值 | 含义 |
|-------:|------|
| `1` | 操作成功 |
| `0` | 操作失败（详见响应中的错误消息） |

预约管理端点返回 `Map<String, Object>`：`{code: 0/1, msg: "...", data: ...}`。

## 6 借阅上限：MAX_BORROW_LIMIT = 5

### 6.1 规则

每位读者最多同时持有 **5** 本未归还图书。

### 6.2 计算方式

```sql
SELECT count(*) FROM borrow
WHERE userId = #{userid}
  AND returnTime IS NULL
```

仅统计 `returnTime IS NULL` 的记录，即**当前手中未还的书**。已归还的不计入。

### 6.3 检查时机

在 `borrowBook` 流程中（两条路径均检查），于 CAS 更新 `isBorrowed` 之前执行：

```java
int activeCount = borrowService.getActiveBorrowCount(userid);
if (activeCount >= MAX_BORROW_LIMIT) {
    throw new NotEnoughException("您当前借阅数量已达上限（5本）");
}
```

### 6.4 边界行为

- 读者已有 5 本未还 → 借书被拒绝（无论基础路径还是增强路径）。
- 预约保留人借书时**同样受上限限制**：即使你有 RESERVED 保留，手中已有 5 本书仍然无法借出。
- 续借 (`renewBook`) **不检查上限**（因为不产生新的借阅记录）。
- 预约创建 (`createReservation`) **不检查上限**（预约不等于借书）。

## 7 CAS 并发控制与重试策略

### 7.1 CAS 操作一览

系统使用两个原子 SQL 实现并发安全：

#### CAS-1：图书状态更新（`BookInfoMapper.updateIsBorrowedCas`）

```sql
UPDATE book_info
SET isBorrowed = #{newStatus}
WHERE bookId = #{bookid}
  AND isBorrowed = #{expectedStatus}
```

返回受影响行数。`0` = CAS 失败（并发竞争中被他人抢先操作）。

**使用场景**：

| 调用 | expected → new | 含义 |
|------|---------------|------|
| 借书（基础） | `0 → 1` | 可借 → 已借出 |
| 还书（基础，无队列） | `1 → 0` | 已借出 → 可借 |
| 还书（增强，有队列） | `1 → 2` | 已借出 → 已保留 |
| 还书（增强，无队列） | `1 → 0` | 已借出 → 可借 |
| 取保留书（增强） | `2 → 1` | 已保留 → 已借出 |

#### CAS-2：借阅归还时间（`BorrowMapper.updateReturnTimeCas`）

```sql
UPDATE borrow
SET returnTime = #{returntime}
WHERE borrowId = #{borrowid}
  AND returnTime IS NULL
```

返回受影响行数。`0` = 已归还（幂等保护）。

**幂等语义**：多次调用 `returnBook` 是安全的。第一次设置 `returnTime`，后续调用发现 `returnTime IS NULL` 不成立，返回 `0`，Controller 层视为"已归还，返回成功"。

### 7.2 重试策略

**当前实现不包含服务端自动重试**。CAS 失败后，Controller 层直接返回错误：

| CAS 失败场景 | 返回的错误消息 |
|-------------|--------------|
| 借书时 `isBorrowed` CAS 失败 | `"图书{bookid}库存不足（已被其他读者借走）"` |
| 增强借书时 `isBorrowed` CAS 失败 | `"图书{bookid}状态已变更，请重试"` |
| 还书时 `borrow.returnTime` CAS 返回 0 | 视为幂等成功，返回 `1` |
| 还书后 `isBorrowed` CAS 失败 | `"图书{bookid}更新库存状态失败"` |

**集成方应在客户端实现重试**：

```
推荐策略:
  重试次数: 最多 3 次
  退避算法: 指数退避 (100ms, 200ms, 400ms)
  可重试条件: 返回 0 且错误消息包含 "请重试" 或 "已被其他读者借走"
  不可重试条件: "借阅上限"、"图书不存在"、"保留已过期" 等业务规则拒绝
```

### 7.3 事务边界

两个 Controller 的 `borrowBook` 和 `returnBook` 方法均标注 `@Transactional`，并采用手动回滚：

```java
@Transactional
public Integer borrowBook(...) {
    try {
        // ... 业务逻辑 + CAS ...
    } catch (Exception e) {
        if (TransactionSynchronizationManager.isActualTransactionActive()) {
            TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
        }
        return 0;
    }
    return 1;
}
```

CAS 操作和业务数据插入（`INSERT borrow`）在**同一事务**内。如果 `INSERT` 失败，CAS 更新也会回滚。

## 8 排队位置管理补充说明

### 8.1 队列位置分配

新预约的 `queuePosition` = 当前该书所有 `WAITING` 预约的 `MAX(queuePosition) + 1`；若队列为空则为 `1`。

### 8.2 管理员调整位置

`adjustPosition(reservationid, newPosition)` 使用三步交换避免唯一约束冲突：

```
1. 将当前记录设为临时值: queuePosition = -reservationId (负数，不冲突)
2. 将目标位置记录设为当前位置: queuePosition = oldPosition
3. 将当前记录设为目标位置: queuePosition = newPosition
```

仅 `WAITING` 状态的预约可被调整位置。

### 8.3 `getActiveReservation` 查询语义

```sql
SELECT * FROM reservation
WHERE bookId = #{bookid} AND status IN (0, 1)  -- WAITING or RESERVED
[AND userId = #{userid}]  -- userid 为 null 时查任意用户
LIMIT 1
```

注意：该查询返回的**不一定是队列首位**。它返回的是 `status IN (0,1)` 中数据库默认排序的第一条。在 `borrowBook` 增强路径中用于快速判断"该书是否有人保留"。

## 附录 A：快速排错指南

| 现象 | 可能原因 | 排查方法 |
|------|---------|---------|
| 还书后预约人无法借书 | 馆员使用了 `/borrow/returnBook` 而非 `/reservation/returnBook`，书被直接释放为 `isBorrowed=0`，被他人抢先借走 | 查 `book_info.isBorrowed` 当前值；查 `reservation` 表中该书记录是否仍为 `WAITING(0)` |
| 书长期处于 `isBorrowed=2` | 保留人未来取书，且无人尝试借该书（惰性过期未触发） | 手动调用 `/reservation/borrowBook` 触发过期检测，或管理员取消该 RESERVED 预约 |
| 借书提示"已被保留给其他读者" | 该书有 RESERVED 状态的保留，当前 userid 不是保留人 | 查 `reservation` 表 `WHERE bookId=? AND status=1`，确认保留人 userid |
| CAS 失败频繁 | 高并发下多人同时操作同一本书 | 属正常行为，客户端实现指数退避重试即可 |
| 借书提示"借阅上限" | 读者手中已有 5 本未还书 | 先归还部分图书再借新书 |
